# Mingus Sports: notes for Claude

Fantasy football site for Josh (joshwilliams332). Live at https://joshwilliams332.github.io/mingus/.
Static pages in `site/`, data built by `scripts/build_data.py` from nflverse (plus Sleeper projections when reachable).
Josh mostly checks the site on his phone, so every change gets checked at ~390px wide as well as desktop.

## How work ships
- Work on a branch, open a PR into `main`, merge it. Merging deploys via `.github/workflows/update-and-deploy.yml`
  (also runs daily at 23:17 UTC and on "Run workflow"). GitHub Pages source is "GitHub Actions".
- The deploy tags `assets/common.js` and `assets/style.css` with the commit hash, so no manual cache busting.
- `site/data/*.json` is regenerated by the deploy; don't hand-edit it.
- Shared helpers (scoring, formatting, ranks, header/footer) live in `site/assets/common.js`.

## Conventions and decisions so far
- Fantasy points are computed in the browser from raw stats (`scoreGame`), so PPR / half / standard and 4- or
  6-point pass TDs can be switched anywhere (`scoringControls`, saved in localStorage).
- **Ranks in parentheses** after stats, e.g. `717 (1st)`, via `rankTag()` in common.js. Top 5 is green.
  - Player pages: season stats ranked against the same position (players with enough games, `minGames`).
  - "Bad" stats (thrown INT, a kicker's missed FGs) still rank most = 1st, but a top-5 rank is **red**.
    A defense's INT are good (green).
  - Teams: points scored / allowed / vs implied per game among NFL teams (`teamAverages`, `rankOf`); fewest allowed = 1st.
  - Over/unders and implied team totals rank within their week and show "of N", e.g. `39.5 (12th of 14)` (`weekLineRanks`).
- **Matchup page (`game.html`)**, top to bottom: score, lines (and results once final), venue, notes, each team's
  last games ("going in" once played), then:
  - before the game: Where each offense can attack (`attackPlan`), then Matchup edges (offense vs defense cards);
  - after the game: Box score only (team stat comparison + passing / rushing / receiving / kicking / fantasy points,
    with a Proj column (Sleeper) or Avg (pre-game points per game) before actual FPTS, green = beat it, red = short).
  - If the score is final but nflverse hasn't published player stats yet, the edges stay up with a note.
- **Teams (`teams.html`) and team pages**: `positionSplits()` in common.js totals every player's game log by
  opponent (defense allowed) and by team (offense produced) per position, per game, ranked 1-32 (1 = most).
  `SPLIT_STATS` lists the stats; INT and sacks are `bad` (more = worse for the offense), so `splitMatchup()`
  flips their colors. Green always means good for the offense attacking that defense (or a strength, for an offense).
  "Where each offense can attack" (`attackPlan` in common.js: soft spots = a defense's bottom 5, tough = top 5, as
  sentences via `splitPhrase`, plus who it helps) lives on the matchup page before kickoff. Team pages only show a
  compact Next game card (lines + link to the matchup); Josh wanted the preview on the matchup, not the team page.
  Below it: Defense by position, an Offense box (team stats from `data/teamstats.json`, ranked; pass rate /
  attempts / carries are uncolored style stats, turnovers and sacks taken are flipped), then a season box score
  (this team's games only; FPTS/G next to the name; name column sticky on phones), then the schedule.
  Josh found the "offense by position" view hard to read, so team pages don't show it (teams.html still can).
- **Start/Sit (`startsit.html`)**: 2-4 players via search, `?p=id,id` in the URL. Ordered by projected points
  (Sleeper, else base = avg of FPTS/G and last 3, × defense-vs-position factor 0.8-1.2, × implied-total factor 0.9-1.1;
  D/ST uses the opponent's implied total). Gap 15%+ = Start, 5-15% = Lean, <5% = Toss-up (tiebreak by ceiling/floor).
  Players whose game is final this week show actual points and are excluded from the verdict.
- **Charts (`analytics.html`)**: a one- or two-week window is a noisy sample. Weak verdicts are worded about that
  window ("In Week 6 alone...") and the full-season r is shown alongside, so a stat isn't written off from one week.
- **Next Gen Stats** on player pages (`ngsCard` in player.html, `build_ngs` in build_data.py; nflverse `ngs_*.csv.gz`,
  week 0 = season totals): QB passing+rushing, RB rushing+receiving, WR/TE receiving. Ranked among same-position players
  who qualify (NGS has play minimums); stats with a clear good direction are colored, style stats (aggressiveness,
  time to throw, depth, cushion, stacked boxes) get grey chips. Non-qualifiers get a one-line note.
  Definitions (`NGS`, `NGS_ORDER`, `NGS_POS`, `ngsRank`, `ngsShow`, `ngsUrl`) live in common.js. Leaderboards are on
  `ngs.html` (Analytics is a dropdown: Chart builder / Next Gen Stats); each stat label and rank chip on a player page
  links to its leaderboard with `hl=` highlighting that player.
  Raw separation is inflated by short targets (Deebo on screens topped it), so `ngsDerive` adds "Separation vs. depth"
  (separation minus a league-wide straight-line fit on target depth). Leaderboard shows volume per game (att / tgt / car)
  and a "Regulars" filter (`NGS_VOL`); on phones it is a one-stat ranked list with a Rank by dropdown instead of the wide table.
- Player game log: Snap %, Opp % (carries + targets share) and Tgt % have header tooltips and a note under the table.
- Phones: player names wrap instead of overlapping tags; grid children have `min-width: 0` so wide tables scroll
  inside their card; team schedule hides O/U, Total and Pts vs implied on small screens.
- **Night-game best bets** (`scripts/nfl_picks.py`, tested in `tests/test_nfl_picks.py`, run by
  `.github/workflows/nfl-picks.yml`, separate from the deploy; it downloads the live site's data JSON instead of
  rebuilding). Night games only (kickoff 7 PM ET+: TNF, SNF, MNF, late-season Saturdays), Josh's choice so football
  uses little of the Odds API key it shares with Hoop Lab. Props pulled once per night game (4 markets: pass / rush /
  rec yds, receptions; 4 credits; event list free; never pulls below `CREDIT_RESERVE`), on the first run within 4 h of
  kickoff, into `data` branch `odds/props/<game id>.json`. Picks lock once into `picks/YYYY-MM-DD.json` (never
  rewritten). Same rules as Hoop Lab: chance = 30% projection + 70% books' no-vig consensus at the most-posted line,
  skip if they differ by 20+ points, >= 54% and >= 3% edge at the best price, prices -200 to +180, one per player, up to
  2 per game, skip anyone Questionable / Doubtful / Out / DNP, regulars only (20 att / 8 car / 3.5 tgt a game), line
  quoted by 2+ books. Projection (Josh asked for the matchup-report approach, Oct 29) = opportunities x efficiency:
  att / car / tgt per game (half season, half last 3) x defense allowed to the position (half strength, 0.85-1.15) x
  team implied vs week average (half strength, 0.9-1.1) x game script (favorites +1% carries / -1% throws per point,
  max 6%) x injury openings (60% of Out/Doubtful teammates' recent volume, by share, max +25%); efficiency = his rate
  steadied toward the position's league rate (40 opportunities) x defense allowed per opportunity (half strength).
  Averaged 50/50 with Sleeper's stat line when players.json has it. Spread = his game-to-game spread blended with a
  typical one (`PRIOR_CV`, 4 games' weight); normal curve. Each pick's "why" (one post reply) leads with projection vs
  line, then the strongest of matchup rank, injury openings, target share / carries, team total, last-5 hits and a
  top-5 Next Gen Stat; the email adds a not-for-posting "Deep dive" with every factor.
  Grading reads nflverse `stats_player_week` (void if the game's stats exist but he has no row). `week-NN-recap.json`
  is written once a week's night games are all graded; `record.json` holds the season record. Week 8 is a test run
  (`RECORD_START_WEEK = 9`): emailed, graded, marked TEST, not counted. Every post carries the 21+ line.
  Delivery: scheduled Claude tasks email Josh (joshwilliams332@comcast.net) at 6:00 PM ET Thu/Sat/Sun/Mon (picks) and
  Tue 1:41 PM ET (weekly recap); they only fetch `picks/` from the `data` branch and send it as written. No model
  backtest exists yet (no historical lines); the public record is the test.
