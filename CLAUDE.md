# Mingus Football: notes for Claude

Fantasy football site for Josh (joshwilliams332). Live at https://joshwilliams332.github.io/mingus/.
Name: **Mingus Football** (Josh, Oct 29, 2026, "for now"; Mingus FF and Mingus Turf Lab were considered). It was
"Mingus Sports", which is now the umbrella brand over Mingus Football and the basketball site, Hoop Lab.
The URL stays `/mingus/`. The `Mingus` JS object and `mingus-*` storage keys keep their names.
Static pages in `site/`, data built by `scripts/build_data.py` from nflverse (plus Sleeper projections when reachable).
Josh mostly checks the site on his phone, so every change gets checked at ~390px wide as well as desktop.

## How work ships
- Work on a branch, open a PR into `main`, merge it. Merging deploys via `.github/workflows/update-and-deploy.yml`
  (also runs daily at 23:17 UTC and on "Run workflow"). GitHub Pages source is "GitHub Actions".
- The deploy tags `assets/common.js` and `assets/style.css` with the commit hash, so no manual cache busting.
- `site/data/*.json` is regenerated by the deploy; don't hand-edit it.
- Shared helpers (scoring, formatting, ranks, header/footer) live in `site/assets/common.js`.

## Conventions and decisions so far
- Fantasy points are computed in the browser from raw stats (`scoreGame`), so PPR / half / standard and 4- or
  6-point pass TDs can be switched anywhere (`scoringControls`, saved in localStorage).
- **Ranks in parentheses** after stats, e.g. `717 (1st)`, via `rankTag()` in common.js. Top 5 is green.
  - Player pages: season stats ranked against the same position (players with enough games, `minGames`).
  - "Bad" stats (thrown INT, a kicker's missed FGs) still rank most = 1st, but a top-5 rank is **red**.
    A defense's INT are good (green).
  - Teams: points scored / allowed / vs implied per game among NFL teams (`teamAverages`, `rankOf`); fewest allowed = 1st.
  - Over/unders and implied team totals rank within their week and show "of N", e.g. `39.5 (12th of 14)` (`weekLineRanks`).
- **Matchup page (`game.html`)**, top to bottom: score, lines (and results once final), venue, notes, each team's
  last games ("going in" once played), then:
  - before the game: Where each offense can attack (`attackPlan`), then Matchup edges (offense vs defense cards);
  - after the game: Box score only (team stat comparison + passing / rushing / receiving / kicking / fantasy points,
    with a Proj column (Sleeper) or Avg (pre-game points per game) before actual FPTS, green = beat it, red = short).
  - If the score is final but nflverse hasn't published player stats yet, the edges stay up with a note.
- **Teams (`teams.html`) and team pages**: `positionSplits()` in common.js totals every player's game log by
  opponent (defense allowed) and by team (offense produced) per position, per game, ranked 1-32 (1 = most).
  `SPLIT_STATS` lists the stats; INT and sacks are `bad` (more = worse for the offense), so `splitMatchup()`
  flips their colors. Green always means good for the offense attacking that defense (or a strength, for an offense).
  "Where each offense can attack" (`attackPlan` in common.js: soft spots = a defense's bottom 5, tough = top 5, as
  sentences via `splitPhrase`, plus who it helps) lives on the matchup page before kickoff. Team pages only show a
  compact Next game card (lines + link to the matchup); Josh wanted the preview on the matchup, not the team page.
  Below it: Defense by position, an Offense box (team stats from `data/teamstats.json`, ranked; pass rate /
  attempts / carries are uncolored style stats, turnovers and sacks taken are flipped), then a season box score
  (this team's games only; FPTS/G next to the name; name column sticky on phones), then the schedule.
  Josh found the "offense by position" view hard to read, so team pages don't show it (teams.html still can).
- **Start/Sit (`startsit.html`)**: 2-4 players via search, `?p=id,id` in the URL. Ordered by projected points
  (Sleeper, else base = avg of FPTS/G and last 3, × defense-vs-position factor 0.8-1.2, × implied-total factor 0.9-1.1;
  D/ST uses the opponent's implied total). Gap 15%+ = Start, 5-15% = Lean, <5% = Toss-up (tiebreak by ceiling/floor).
  Players whose game is final this week show actual points and are excluded from the verdict.
- **Charts (`analytics.html`)**: a one- or two-week window is a noisy sample. Weak verdicts are worded about that
  window ("In Week 6 alone...") and the full-season r is shown alongside, so a stat isn't written off from one week.
- **Next Gen Stats** on player pages (`ngsCard` in player.html, `build_ngs` in build_data.py; nflverse `ngs_*.csv.gz`,
  week 0 = season totals): QB passing+rushing, RB rushing+receiving, WR/TE receiving. Ranked among same-position players
  who qualify (NGS has play minimums); stats with a clear good direction are colored, style stats (aggressiveness,
  time to throw, depth, cushion, stacked boxes) get grey chips. Non-qualifiers get a one-line note.
  Definitions (`NGS`, `NGS_ORDER`, `NGS_POS`, `ngsRank`, `ngsShow`, `ngsUrl`) live in common.js. Leaderboards are on
  `ngs.html` (Analytics is a dropdown: Chart builder / Next Gen Stats); each stat label and rank chip on a player page
  links to its leaderboard with `hl=` highlighting that player.
  Raw separation is inflated by short targets (Deebo on screens topped it), so `ngsDerive` adds "Separation vs. depth"
  (separation minus a league-wide straight-line fit on target depth). Leaderboard shows volume per game (att / tgt / car)
  and a "Regulars" filter (`NGS_VOL`); on phones it is a one-stat ranked list with a Rank by dropdown instead of the wide table.
- Player game log: Snap %, Opp % (carries + targets share) and Tgt % have header tooltips and a note under the table.
- Phones: player names wrap instead of overlapping tags; grid children have `min-width: 0` so wide tables scroll
  inside their card; team schedule hides O/U, Total and Pts vs implied on small screens.
- **Fantasy focus (Josh, Nov 3, 2026).** This site covers fantasy football only. Picks, odds pulls, grading, the prop
  tool and the game simulator live in `joshwilliams332/mingus-picks` (which copies the projection model from this repo
  and reads this site's data and tuned settings), so they don't get added here. Vegas lines are used only as an input
  (implied team totals). Don't write the reasons for this in the repo, PRs or commits.
- **Projection model** (`scripts/projections.py`, tested in `tests/test_projections.py`): passing / rushing / receiving
  yards and catches for every regular as opportunities x efficiency, with a game-to-game spread. att / car / tgt per
  game as a recency-weighted average (4-game half-life) blended with team-first volume (below, which also carries
  injury openings) x defense allowed to the position (quarter strength) x team implied points vs week average (eighth
  strength), each capped at 0.95-1.05; efficiency = his recency-weighted rate (6-game half-life)
  steadied toward the position's league rate (`RATE_PAD` 20 opportunities; `RATE_PAD_BY`: passing 100, TE catches 50)
  x the defense's per-play rate (quarter strength); x `MEAN_ADJ` (1.06; passing yards x0.93). Averaged 50/50 with
  Sleeper's stat line when players.json has it. Spread = his game-to-game spread blended with `PRIOR_CV` (counted as 12
  games) x1.225; log-normal for rushing / receiving yards and catches, bell curve for passing yards. `median` = his
  typical game (the middle of the range); quote it, not `mean`, in words: skewed stats' mean runs ~10% above actual
  averages while the middle is right (actual above it 50-52%, 2016-2025).
  **Ten-season retune (Josh, Nov 9, 2026):** replayed 2016-2025 (43,442 projections, each from earlier games only) and
  2026. Scored with `evaluate_multi` in `scripts/backtest/engine.py`: the over at five lines (0.6-1.4x his average) per
  projection, plus average miss and bias. The old one-line test (floor(average) + 0.5) mostly tested the range's shape
  and rewarded projecting high. Settings `SETTINGS_VERSION` 2: better in all 10 seasons and on 2026 (multi Brier
  0.2119 -> 0.2113; 2016-2025 0.2138 -> 0.2130). Gains from settings alone are small; bigger gains need new
  information (team volume shares, depth chart / QB changes). Stronger pulls toward the league average (100-800) did
  not help on 10 seasons except for passing. Tested and dropped earlier: game script, discounting low-snap games.
- **Team-first volume** (Josh, Nov 9, 2026; `team_first` in projections.py, `tfa/tfc/tft/thl/tgap` in the engine).
  Volume = his own recent average blended with the team's recent volume (16-game half-life) x his recent share of it,
  re-scaled among teammates who may play (not Out / Doubtful / reserve, missed at most one team game since their last).
  Weights `TEAM_FIRST`: pass attempts 0.25, carries 0.5, targets 0.5. Replaces the old `openings()` boost: a ruled-out
  teammate leaves the share split, so his work moves to who's left (`parts.f_inj` / `parts.out` still show it).
  Backtested with nflverse weekly rosters + injury reports (only what was known before kickoff): multi Brier 2016-2025
  0.2130 -> 0.2117, better in all 10 seasons; 2026 0.2113 -> 0.2109. The old openings boost on top made it worse.
  Knowing exactly who played (hindsight) would be worth about twice that, mostly from backup QBs and depth-chart
  changes, which is what depth-chart / QB-change flags would add. `SETTINGS_VERSION` 3.
- **Chance to score** (`td_chance` in projections.py; Josh, Nov 1). Logistic on 2021-2025 player games from earlier
  games only: recency-weighted (4-game half-life) carries, targets, red-zone carries and targets, TDs per game, his share
  of the team's red-zone carries / targets, team implied points vs the week average, position. Calibrated out of season;
  chances over 50% pulled in 20%. Brier 0.1674 (2021-25 held out by season) / 0.1790 (2026), vs 0.1738 / 0.1919 for his
  own TD rate. Defense TDs allowed to the position and inside-10/5 usage added nothing (dropped). Rushing + receiving TDs
  only. Doesn't know depth-chart news (e.g. a goal-line back returning). Backtest: `scripts/backtest/td/`. Not on the site yet.
- **Reserve list = Out** (Nov 9, 2026): `reserve_status` in build_data.py marks players whose latest nflverse roster
  status is RES / CUT / RET / EXE / SUS as Out (`injury.reserve`, label like "Injured reserve"; tag "IR" / "CUT") unless
  this week's injury report lists them. They're left off the home page injury report. Team first only counts teammates
  who missed at most one team game, so long-term absences aren't counted twice.
- **Model review loop** (`scripts/model_review.py`, `.github/workflows/model-review.yml`, tested in
  `tests/test_model_review.py`; Josh, Oct 31: "improving after every single game"). Separate from the deploy. Every run:
  (1) snapshot every regular's projection and chance to score for games not yet kicked off into `data` branch
  `model/projections/<season>-wNN.json` (frozen at kickoff); (2) score every saved game with a published box score into
  `model/scorecard.json` (by week / game day / stat: average miss, bias %, Brier vs coin, ours vs Sleeper vs the 50/50
  average, the chance-to-score scorecard, biggest misses); (3) once per finished week W (all games' stats out, W >= 6):
  local search from the current settings (one grid step either way per setting, twice) on 2016-2025 + this season's
  weeks < W counted x4 (`THIS_SEASON_WEIGHT`), scored with `evaluate_multi`; adopted only if it beats the current
  settings in at least 70% of the past seasons on their own (`SEASON_WINS`) and isn't worse on week W
  (Nov 9: one week of ~300 projections is mostly noise) -> `model/tuning/wNN.json`, and if adopted `model/settings.json` (read by `projections.apply_settings`
  and by mingus-picks) + `settings-history.json`; (4) `model/report-wNN.json` / `report-latest.json` with a
  ready-to-send email. `migrate_settings` replaces a `settings.json` older than `SETTINGS_VERSION` with the code's
  defaults (logged in the history). Retuning needs past seasons in `hist/` (Actions cache, 2016-2025), this season's `stats_<season>.csv` and
  `games.csv`; `scripts/backtest/engine.py` must keep mirroring `projection()`.
